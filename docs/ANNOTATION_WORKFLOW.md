# 人工事件审核与监督标注的准备流程

分发请用 `deliverables/annotation-20261117-v2-plain/` 中的 A/B 简明版 ZIP。完整解压后打开 `00_从这里开始.html`，按包内操作说明完成第②、③页，再导出 JSON 交回。简明版沿用上版批次编号，已填写的同字母回收文件可以导入。回收与仲裁衔接见 `outputs/annotation_delivery_20261117/coordinator/协调者交接说明.md`。下文记录早期待审模板的工程准备。官方 152 条在开发阶段隔离，方法锁定后才用于最终评测。

本轮生成的是待处理材料包，不是标注完成结果。其 `human_event_review_complete` 与 `training_ready` 始终为 false，reviewer、label、features、证据及仲裁结论保持 null，不能据此通过训练准备检查。

```powershell
python -X utf8 tools/prepare_annotation_package.py
python -X utf8 tools/prepare_annotation_package.py --verify-only data/annotations/pending/review-20261117-01
```

脚本只读取原始 train/val 与候选划分，核对其 SHA-256，且只导出声明文本、声明日期/地点与原图引用。数据集标签、QA、核查文章、事后解释和 metadata 均不导出。原始文件、候选划分和正式配置不被修改。重跑拒绝覆盖已有包，以免覆盖人工填写；需要新的空包时使用新的 `--package-id`。

## 先审核事件划分

`event_review/reviewer_a` 与 `reviewer_b` 分别交给两位互不查看结论的人员。每份包含全部 945 条声明、815 个候选组和已有同组关联对。`claims.csv` 可填写接受/否决候选组、建议的新事件 ID、需合并的其它组与理由；`candidate_links.csv` 可逐对复核现有同组关系。已有分组可能由文本、图片、URL等启发式关联得到，不等于真实同事件；公开图文不能直接支持的关联明确标为待独立确认，不展示数据集金标准 QA/答案来提示结论。

审阅者必须同时检查“错误合并”和“跨组漏合并”。候选关联对只覆盖已有组内组合，不能证明其它组之间没有事件关联。最终官方 val 的 152 条完整保留，训练中与之关联的 4 条当前隔离；这些都是待人工核准的候选状态。全量事件审核中可查看最终评测的公开图文，但不得访问/抄入其标签、QA或核查解释，更不能把最终评测材料送入模块训练或检索。

两位意见冲突时交第三人仲裁。协调者据已签名的实际审核记录修订分组、检查所有用途间的事件隔离，再生成锁定划分；不得直接把原候选文件的布尔值改为 true 来替代审核。`private/claim_key.json` 仅供协调者把中性 C/G 编号映射回原索引，应与独立审核材料分开保管。

## 再采集真实证据与三类监督

`annotation_review` 的两个独立副本各有 210 份任务模板：45 条模块拟合声明 × 来源、质量、充分性三类，共 135 份；15 条独立温度校准；60 条来源机制验证。这是任务模板数，不是合法标注条数；一个声明可能需要多对来源片段、多个原子声明或多个已执行历史。没有对应证据/历史的工作单保持 null。

每一项只能依据真实归档网页/请求及实际模型状态填写：

| 用途 | 要先取得什么 | 人工判断与数值材料 |
| --- | --- | --- |
| 来源模块拟合 | 当前两条实际片段、引用链/首发等核验材料 | 同源 / 独立 / 无法核实；6维可观测来源特征 |
| 质量模块拟合 | 指定原子声明与一条实际片段 | 出处可溯性、完整性、适用性的审核及3维特征 |
| 充分性模块拟合 | 实际推理历史、预测与引用片段 | 现有引文是否足够；7维状态/校准特征 |
| 温度校准 | 独立15条声明上冻结模型的真实logits | 由独立审核/既定开发标签协议提供的类别，不得从最终评测搬运 |
| 来源机制验证 | 独立60条声明的真实片段对与核验材料 | 独立人工关系评测；不可复用模块拟合标注 |

特征名与顺序遵循 `docs/DATA_CONTRACTS.md`；没有取证、没有真实模型输出，就无法合法填写这些特征。不得用零向量、随机数、数据集真值生成的立场或自动模型“签名”补齐。核查失败/无法核实与未标注是不同状态：空模板的 null 仅表示没有完成工作，不能直接当作已审核的无法核实，更不能当成独立来源或负例。

取证时保存真实 URL、UTF-8 快照、SHA-256、取得时间、准确片段位置及真实请求账单；证据使用中性 ID，不把方法名称或实验目录路径发给审核者。来源审核材料不带方法、基线路由、模型输出或内部方法路径。模板中的证据槽位均为空，后续采集仍需保持此盲法边界。

## 独立填写与仲裁

向审核者 A、B 分别分发各自文件夹，禁止把 A 的已填结果复制给 B。CSV便于分派和填写简单审核字段；JSONL保留完整证据和模型状态槽位。两份材料中的审核者 ID 都故意为空，实际参与者填写自己的真实、不同身份。`adjudication` 提供空白合并工作单；脚本不判断分歧，不替任何人签名。

审核完成后由协调者核实证据与签名，再转成研究执行器要求的规范 JSONL（包含原始 claim_id/event_group、实际 features、ReviewedLabel 与 evidence_proofs）。当前 pending 模板不是该格式，不会覆盖 `data/annotations/source.jsonl`、`quality.jsonl` 或 `sufficiency.jsonl`。需要仲裁的记录必须保留第三人及实际结论；空白和未决行不得进入训练。

本轮校验只证明任务数量、输入白名单、图片引用/哈希、空审核字段和包内文件完整性符合生成协议。它不证明分组正确、标注存在或任何研究性能。
