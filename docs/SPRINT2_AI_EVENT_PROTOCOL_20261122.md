## 二　固定证据与模型输入

1. 训练知识库 ZIP 的 SHA-256 为 `6c4e8e2c92e3c352e61c0ae447da0da619e18c8e9c33f269ddfee7310eba6eb9`。工具从公开配文、记录地区及原子声明生成查询。每条最多收录 4 个片段，先取最多 2 个 RIS 片段，再从文本轨补足。混合检索使用本地 MiniLM 与 MMR，系数为 0.65。这个取证预算与历史先导报告中的 top-6 分别记录。
2. 逐张核验原图哈希后以冻结的本地 Qwen2.5-VL-7B-Instruct、NF4、最多 200,704 图像像素处理声明。原子声明、规范事实、五个评分通道、终端四类单 token logits、引文及解释均保存原始调用。提示只用公开输入、实际检索文字和既有模型状态。用于充分性审核的结论是这次冻结预测。
3. 每个片段的取得时间、网页 URL、UTF-8/LF 快照、SHA-256、起止字符位置及精确引文进入私有归档。区间为左闭右开，按 Unicode 码点计数。RIS 命中或网页出现日期本身不足以确认图片首发和作者。这类记录的图像出处标记为未核实。网页上出现的原始新闻叙述保留原文。
4. 本轮的目的在于产生可独立审核的初始历史。人工监督到手前，逐原子质量权重采用三个实测质量值的均值，软来源依赖取直接引用、已核实视觉同源、文本近重复三项中的最大值。现有二次规划据此解出正反通道。全部原始分量可复算。这项初始化及其温度参数只绑定当前这批固定历史，后续训练出的模型另行登记。[采集配置](../config/sprint2_fixed_annotation_v3.json) · [采集程序](../tools/collect_sprint2.py)

## 三　抽题、特征与返还

| 审核对象 | 抽取规则 | 私有输入 |
| --- | --- | --- |
| 来源 | 每个有候选对的声明选软依赖最高的一对；并列按检索顺序。45 条拟合与 60 条机制验证各自使用其所属分组。 | 直接引用、时间接近度、已核实视觉同源、字符三元组相似度、同域、时间可用，共 6 维。 |
| 质量 | 按 45 条拟合声明的数字 ID 排序，循环选择排名片段和原子声明。 | 出处可溯性、片段完整性、对指定原子的适用性，共 3 维。 |
| 充分性 | 每个拟合声明使用一次实际终端预测和它选择的引文。空引文明确标出数量，下方展示当时可见的上下文。 | 引文事实覆盖、已核实图片出处、正反通道均值、两通道逐原子较小值的均值、最大校准概率、引文可回放，共 7 维。 |

来源评测采用上述选对策略，后续 Brier 结果适用于这批有意富集的候选对。质量与充分性也只对应选定片段或冻结历史。公开 E 编号限于各自声明；协调者的映射把这些编号还原为知识库证据 ID、快照哈希和字符区间。

E1 另有一项状态偏差比较。仓库要求同一规范事实的全部来源对都取得可判定的关系，才能为该声明计算 Oracle 状态。检查最早完成的 6 条机制验证历史时，已发现主表之外有 11 对属于这一情况。在收到任何监督标签之前，确定了补充规则：纳入全部 60 条机制验证历史中规范事实键完全相同、且未在主表出现的来源对。补充包单独回收，私有用途记为 `oracle_coverage`，不计入主表 Brier。若双审后仍有关键关系为 null，该声明的 Oracle 状态偏差继续记为缺失。

校准只从保留的 15 条提取训练侧类别，与已冻结的四类 logits 配对拟合一个共享温度。105 条待审声明的标签与 QA 未进入提示或盲包。审核员能看到公开声明、原图、所审片段及离线全文。充分性任务另显示待审预测和它的实际引文。`task_objects.json` 留在协调者侧。[数据接口](DATA_CONTRACTS.md)

试标选数字编号最前的 3 条拟合声明和 2 条机制验证声明。试标与全量使用相同的材料、固定任务编号和判断范围。甲乙独立工作。全量页支持导入本人同席位的试标 JSON，同一任务只计一次。填写“无法核实”时保留 null 并说明缺少的依据。材料缺失时登记待补。上述甲乙 HTML 和真人工具记录原设计，并作为固定公开材料的可视化参考。按后续决定，实际标注使用独立的 ZCode 机器回收格式。对 GLM 参照的来源结果与模型引文审计均明确标记机器来源。[回收验真](../tools/validate_annotation_return.py) · [规范转换](../tools/convert_annotation_return.py)
