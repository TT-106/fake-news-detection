# 下轮实验怎么做

**先在训练先导的 20 条图文上保存真实取证过程，并检验我们是否有足够多能通过核查来源改变判断的案例。** 这与两人检查分组可以同时推进。等证据和标注齐备，再用同一个 Qwen、同一批候选证据和同一预算，验证我们的来源核查策略比简单规则多带来多少收益。

本地已跑通 RTX 4060 8 GB 上的 Qwen2.5-VL-7B NF4。固定 20 条的零检索实验中，图文和纯文本都输出「证据不足」，正式 E1–E4 和论文复现尚无成绩。重新用 `config/experiment.example.json` 检查，仍缺三类人工监督、真实取证归档和已审核事件划分。示例配置中的预算与阈值待开发实验锁定。依据见[先导协议](PILOT_PROTOCOL.md)、[本地准备检查](../src/real_averimatec_pipeline.py)和[分发回收流程](ANNOTATION_WORKFLOW.md)。

## 两条工作并行推进

| 谁做 | 先做什么 | 本轮交付 |
| --- | --- | --- |
| 两位审核者 | A、B 各自检查同一批 945 条图文和 187 对关系，各自交回 JSON。协调者可以先检查少量返回的格式、理由能否复查，再收齐全量。 | 两份独立原始文件，按图文 ID 列出的分歧和缺项，以及核定后的事件与素材分组。跨训练与评测的关联优先核查，需要时由第三人处理分歧。 |
| 工程与实验 | 从已固定的 20 条训练先导开始，复用真实搜索和快照流程，逐步跑通图文初始检索。只凭配文、原图和允许的事前信息生成查询。在同一初始证据上，能做时分别实际执行一次补事实、追图源、核同源，并保留停止作为对照。 | 每条的查询、候选证据、网页快照、可定位引文、发布时间、实际耗时、token、工具调用、失败和决策。另列命中有用证据、有可追溯来源对、来源核查实际改变结果的案例数。失败和空返回保留在分母中。 |
| 协调者 | 先挑少量训练用的真实材料试标。来源给固定证据对，质量给固定命题和片段，充分性给固定模型结论及实际引用。两人拿同一版本和同样的证据编号。 | 可回放的小批试标材料及双人结果，确认“未拿到材料”“看后无法核实”“已判断”可区分。随后给 210 个工作单补材料，按实际可用的事件组、类别和标签数量扩大。 |

取证先导使用训练池。官方 152 条开发集继续按当前项目协议作锁定后的内部终评，352 条赛道盲测数据留给同协议对标。正式训练和机制验证在事件组隔离确认后进行。真实网页轨迹和官方资料库检索各自记账，保留各自的评测口径。没有可用的反向搜图工具时记录该分支不可用。取证快照、哈希与成本格式见[数据接口](DATA_CONTRACTS.md)。

## 先验证哪条假设

**当几条证据可能来自同一个源头时，我们能否选出最值得核查的那一对，在相同预算下减少错误判定？** 例子是三家网站转发同一份通稿。查明是转载有时会改变独立证据的数量，有时即使查明也改变不了结论。χ 把「来源关系还不确定」和「查清这对关系会多大程度改变当前证据状态」相乘。来源核查能否查到答案、实际结论能否变好，需要另测。来源依赖本身已有研究，选择最有用的来源核查动作才是本项目待验证的贡献。依据见[来源依赖先例](https://doi.org/10.14778/1687627.1687690)和[χ 实现](../src/core_models.py)。

1. **看机会大小。** 在预先选定的训练先导里报四个数。多少条找到了可用证据，多少条存在可核的同一事实来源对，多少次真实核查得到明确关系，多少次改变了原判断或降低了损失。用少量真实人工确认关系看 E1 的状态变化，再看最终判断是否随之改变。E1 的状态更接近人工来源上界只能支持状态层结论。
2. **拆开看谁带来收益。** 先跑现有的无检索对照和预算内固定图文检索，再加来源去重或 MMR。用同一批真实分支比较完整 χ、去掉 χ、只按来源不确定性 `p(1−p)`、匹配置换。对齐证据池、骨干、总调用或 token 上限、失败成本与终止规则。E3 看所选动作离事后最优有多远，同时记录查对后反而改错、证据够但模型仍出错的样本。代码细节见[实验执行器](../src/experiment_runner.py)。
3. **报告可反驳的结果。** 预先定义来源重复、同域独立、跨域转载、旧图复用及无来源疑点的子集，分别公布样本数和结果，并保留全体成绩。重复素材和同一事件按事件组做配对区间。当前 `paired_bootstrap` 按声明抽样，正式组级区间需补实现。开发组先定单个主要预算点与最小有意义增益。正式比较看相同预算、有实质差值且配对区间支持提升，同时报告覆盖率、错误率、各类 F1、实际调用数和耗时。覆盖率过低时，低错率需要结合暂缓比例解释。依据见[本地指标实现](../src/research_evaluation.py)。

如果先导里大多数案例缺可用证据，就先改检索和证据定位。如果来源查清了却基本不影响决策，优先验证用更简单的去重和固定检索能否达到同等结果。只有可能被来源动作改变的案例才有机会通过这项机制直接改对，机会很少时要同时报告真实发生率与该类样本的改善。若同水平正确率下实际费用或耗时更低，可把结论限定为该预算下的效率优势。20 条先导用于选研发方向，正式分数依赖独立测试。

## SOTA 要过的两道对照

**方法对照。** 4060 上固定 7B，先完成同条件的强检索基线及去重对照。REVEAL 用了同名 Qwen2.5-VL-7B-Instruct，是首选论文方法参照。想低成本验证方法，也可优先适配 AIC CTU 的双路检索加一次判定结构，记录更换骨干、量化和证据库带来的协议改变。共享候选证据、检索和推理预算，才能把相对收益归因于方法。依据见[REVEAL](https://aclanthology.org/2026.fever-1.8/)、[AIC CTU](https://aclanthology.org/2026.fever-1.11/)与[组织者方法设置表](https://aclanthology.org/2026.fever-1.6.pdf)。

**官方排名对照。** FEVER-9 在独立的 352 条盲测上用 AVerImaTeC score。按该赛道要求，结论正确且证据达标才计分。主办方公布的冠亚军是 HUMANE/VILLAIN `0.5455` 与 ADA-AGGR `0.5369`。VILLAIN 使用 Gemini-2.5-Pro 和扩充后的官方资料库。正式对标时先确认官方测试入口是否仍接受新评测，或落实相同官方评分代码、评审模型、证据格式和时间限制。官方评分采用 Gemma-3-27B，评分资源的可用性需要单独核验。等方案和预算锁定，再运行 352 条并报告同一计分口径、可比结果以及预算。依据见[官方成绩](https://fever.ai/task.html)、[组织者论文](https://aclanthology.org/2026.fever-1.6.pdf)、[评分代码](https://github.com/abril4416/AVerImaTeC_Shared_Task/blob/main/prepare_submission/eval_offline.py)和[VILLAIN 论文](https://aclanthology.org/2026.fever-1.9/)。

本地 152 条里，141 条是 `Refuted`，另外三类只有 4、6、1 条。对这 152 条始终预测 `Refuted` 就有 92.76% 裸准确率，但按四类等权计算 Macro-F1 只有 0.2406。这是类别分布诊断，表明裸准确率会掩盖少数类问题。内部评测保留全量四类 Macro-F1、各类样本数、固定预算和覆盖率下的风险，以及人工引用审核。声称整体 SOTA 需要官方可比评测。相同预算下少查而不更错，可以单独报告为该设置下的质量与成本优势。分布依据见[本地数据核查账本](../outputs/progress/results_audit.json)。

各参赛方法的配置、数据版本及证据判分差异集中记录在[公开对照核查](baselines/SOTA_LANDSCAPE_20261118.md)。
