# CADE-FND 工程可提取性核验

核验日期：2026-10-22。范围：官方配置、固定版本实现和数学一致性；未安装依赖、未加载模型、未运行训练、未测量本机吞吐。按用户最新说明，算力可用，显存不作为方法取舍依据。

## 核验结论

冻结开放权重 VLM 的概率、隐状态和部分注意力信号具有实现路径；原文的测量定义与训练目标尚未完全自洽。首要问题是预测位置、对照条件和梯度路径，随后才是效率。以下“代码事实”限定于明确版本，不外推所有 Transformers 版本。

## 一、概率和注意力需要先明确测量语义

**官方配置事实：** Qwen2.5-VL-7B-Instruct 的文本解码器为 28 层、28 个 query heads、4 个 KV heads，词表大小 152064；视觉 patch 为 14、空间 merge 为 2。不能把 4 个 KV heads 当作 4 张输出注意力图，也不能把 3B 配置或配置类的默认参数当作 7B 检查点配置。[官方检查点配置](https://huggingface.co/Qwen/Qwen2.5-VL-7B-Instruct/raw/main/config.json)

**固定源码事实：** Transformers v4.51.3 将视觉 embedding 放入解码器图像 token 位置；输出的 decoder attention 是统一序列中的 self-attention。其 logits 通过当前位置隐状态产生，并使用前移一位的 labels 计算损失。eager 可返回注意力；SDPA 在请求权重时回退手工计算；每层权重被加入 `all_self_attns` 后整体返回。核查位置：图像注入 L1597–1614；logits/shift L1675–1683；eager L669–695；SDPA L813–828；收集 L1041–1093。[固定版本源码](https://raw.githubusercontent.com/huggingface/transformers/v4.51.3/src/transformers/models/qwen2_5_vl/modeling_qwen2_5_vl.py)

**据此推导的测量约束：**

1. 若原文 token 为零基索引 `i` 的 `w_i`，预测它的分布应读取完整多模态序列中的 `logits[i-1]`，同时计入聊天模板、视觉 token 展开和 padding 的位置偏移。不能直接把文本原始字符索引当作模型位置。
2. 若要提取“预测该词之前”的注意力，query 也应选择 `i-1`；若选择 `i`，它已观察到该词，属于输入该锚点后的上下文特征。后一种设计可以研究，但必须与预测前熵区别命名。新闻原有词作为输入本身不构成标签泄漏；把真伪答案或标注理由放进探针输入才会泄漏。
3. 图像应出现在被测 query 的因果可见前缀中，否则该 query 无法看到后置视觉 token。要保存实际序列和 image-token mask，不能只检查界面上文字顺序。
4. 多 token 实体必须规定首 token、全 span 平均、最大值等聚合方式。后续子词可能被已知实体前缀高度约束，这不是视觉证据。
5. 若整篇新闻在更早的提示中出现、后面再要求模型补写同一实体，高似然可能来自拷贝。必须说明新闻文本究竟在哪个位置出现，是否重复。

这些是因果语言建模与实验定义的一致性要求，不是该探针已能识别假新闻的证据。

## 二、熵、实体似然与 JS 不是同一个测量

设 `p_i(v)` 为预测锚点下一个 token 的完整词表分布。

- `H(p_i)` 是词表分布分散程度，没有使用实际锚点词 `w_i` 的概率。模型若自信地预测另一个地名，熵仍可能很低。
- `-log p_i(w_i)` 是观测锚点的 surprisal；它和词表熵的研究含义不同。稀有姓名、分词长度及语言先验都可影响它。
- `JS(p_i^I,p_i^mask)` 对称且非负，不能表达“遮挡后实体概率上升”的方向。原文所谓负向增益必须另立一个有符号量，例如 `log p_i^I(w_i)-log p_i^mask(w_i)`。
- 只有固定相同模板、同一新闻前缀、同一词表和相同位置，两个概率分布的差异才可归于选定视觉操作的响应。不能比较两段自由生成后不同历史下的第 k 个分布。

以上均为定义直接推导。建议在提取结果中同时保存熵、实际锚点 surprisal、有符号似然差和 JS，后续分别检验；不要把它们统称已证明的“冲突信息增益”。

## 三、三个视图对应多次条件求值

原图与掩码图的 JS 至少需要两个图像条件下的模型求值。若空图用同一新闻、同一位置进行校准，则每条还需要一个空图求值，共三个；前景、背景分别遮挡或做多个随机对照，还会继续增加。合并成一个 batch 只减少调用次数，不会把三份条件计算变为一份。

“不进行自回归生成”可以成立；“整个方案只有单次前向开销”不成立。准确表述应为：每个视图做一次 teacher-forced prefill，多个视图离线提取。实际总耗时应包含图像预处理、锚点提取、全部视觉条件、特征聚合及缓存写入。

离线缓存使下游调参较便宜，这是合理工程方向；但如果改变上游模型、量化、模板、选层、分辨率、mask 或实体选择规则，缓存可能必须重算。缓存标识应覆盖这些参数及数据内容哈希。

## 四、一次空图校准不等于移除模型的固定 sink

由注意力定义，权重取决于该层 query、key、位置及可见序列。文本变化会改变 query；视觉 token 网格变化会改变 key 位置与数量。因而“灰图 + 通用模板”得到的一个向量没有天然的逐样本可比性。

[官方模型卡](https://huggingface.co/Qwen/Qwen2.5-VL-7B-Instruct) 提供动态视觉 token 数与分辨率控制示例；[官方版本文档](https://huggingface.co/docs/transformers/v4.51.3/en/model_doc/qwen2_5_vl) 列明 `image_grid_thw`、processor 和多模态 forward 接口。读取范围为模型卡 Quickstart/分辨率示例及文档接口。

可复现实现至少应区分：

| 校准方案 | 可作的有限解释 | 需要验证的事项 |
|---|---|---|
| 同文本、同网格、同位置的逐样本空图 | 对该输入的空图条件响应作差 | 仍可能混合内容变化与 sink，且需额外求值 |
| 按网格和位置分组的校准集平均 | 经验估计的位置/输入先验 | 校准集仅来自训练数据；在独立验证集比较稳健性 |
| 单通用模板空图 | 近似位置模板 | 不能宣称严格校正所有输入；须与前两项及不校准对照 |

空图的原始像素零值、灰色 PIL 图像与处理后全零张量也不能不加区分。应固定原始图像颜色，并让原图与空图经过同一 processor。

此外，原式 `a/(sum(a)+epsilon)` 总和严格小于 1；当 ReLU 后全零时它产生全零向量，其“熵”数值接近 0，却不代表精确定位。应保存残余总量，低于阈值时记为缺失/校准失败，其他情况再严格归一化。空图减法是否提高预测力属于待检验假设。

## 五、层与头的操作应成为实验配置

选层 14–18 不是由 28 层架构自动推出的最优区间。可在训练/验证集预先比较，不可观察测试标签后挑峰值。

先求跨头/跨层平均再求熵，与先逐头求熵再平均不等价。两个头各自集中在不同位置时，后一者都可能低熵，前一者却更分散。必须登记聚合顺序，并同时保留视觉注意力总量；只对视觉子集归一化会抹掉“几乎没看图”的区别。

为使测量可信，首次小规模运行需断言：输出 attention 非空、所有值有限、query/key 维度与序列一致、图像位置数量与网格一致、对相同输入重跑的数值稳定。eager、SDPA 与 FlashAttention 不应只因加载成功就视为等价的“完整权重导出”接口。[官方 attention 后端说明](https://huggingface.co/docs/transformers/en/attention_interface)

## 六、冻结特征上的 margin loss 无法训练分类器

原文将 `u` 离线缓存并冻结，再定义：

`L_total = L_BCE(theta) + lambda * L_margin(u_real,u_fake)`。

若 margin 项没有包含任何可训练参数，则对分类器参数 `theta`：

`d L_margin / d theta = 0`。

因此它只是对总损失加上常数，不能促使冻结的“真假双熵拉开”。这是梯度路径直接推导，与实现速度无关。[PyTorch autograd 官方说明](https://docs.pytorch.org/docs/2.14/notes/autograd.html) 解释仅有关联可训练输入的运算进入所需反向图。

实现纠错有两个明确选项：先仅使用 BCE，或将 margin 放在可训练 `h_theta(u)` / 分类器表征上。后者只能解释为监督学习后的表征间隔，不可再声称原始熵被训练成了真值分解。

## 七、残差结构没有泛化性能保底定理

`F_final = F_sem + g * Proj(F_cross)` 允许表达基线附近的函数，不保证优化得到该函数，也不保证测试风险不增。

直接反例：一维 `F_sem=1`，残差投影为 `-4`，门值 `g=0.5`，则 `F_final=-1`；按符号分类的原正确结果可以被翻转。sigmoid 门在有限参数下也不精确等于 0。即使额外加入可置零的系数，只能保证包含基线的表示能力，不能保证训练或泛化性能。

工程上保留冻结的基线模型与相同数据协议，验证集分别选择“基线”或“增强模型”，可以提供可回退的部署流程；这是经验选择，不是锁死真实风险下限。

## 八、可复现记录的最小集合

首次探针运行建议记录：数据样本/事件 ID 与拆分、图像/文本哈希、模型 revision、processor/tokenizer revision、Transformers/PyTorch/CUDA 版本、精度或量化配置、attention 后端、模板文本、视觉网格与完整 token 位置、锚点与分词 span、query 选择、层头和聚合规则、mask/填充/随机种子、null 校准方式、每视图前向次数、总耗时、失败样本与缓存键。

这些记录能支持定位失败来源，不能替代新闻标签和机制验证。当前没有模型运行证据，故所有吞吐、稳定性和下游增益均未验证。

## 附录：原文资源承诺的短核验

用户已说明显存不是问题；以下仅纠正原稿，不能据此否定科学方向。

固定源码先收集所有层完整注意力，返回后切片无法降低已经发生的峰值。按配置，在 batch=1、28 层、28 heads、每元素 2 字节时，返回张量量级为 `28*28*S*S*2` 字节；S=1024 为 1.531 GiB，S=2048 为 6.125 GiB，尚未计模型、logits、临时 softmax 和其他内存。该数值由张量尺寸计算，不是实测。

若需要减少完整权重保存，应在层执行期间选择性聚合或实现只算 query 行的探针，而非事后 `del outputs`。`empty_cache()` 不释放仍被引用的活跃张量。[PyTorch 官方文档](https://docs.pytorch.org/docs/2.14/generated/torch.cuda.memory.empty_cache.html)

4-bit 通常压缩可量化线性层的权重，并不将所有计算或中间张量变为 4-bit；Windows 的量化支持应按具体版本核查。[bitsandbytes 官方说明](https://huggingface.co/docs/transformers/en/quantization/bitsandbytes)

因此“峰值 <6.2GB”“0.14s/样本”“全量20–30分钟”“20个epoch不到1分钟”都只能在锁定硬件、软件、数据规模、序列/分辨率、视图数及测量边界后实测，不应作为已有事实。
